# Entscheidungs-Log (Spielregeln)

Zweck: Jede festgelegte Regel **einmal** sauber notieren, damit dieselbe Sache nicht 4× neu „gefixt“ wird.

**Bei jedem Bug zuerst hier nachsehen:** Stimmt die Regel → es ist ein Daten-/Probe-Problem. Regel falsch → **hier** ändern und an **der einen** Funktion umsetzen.

Format pro Eintrag:

```
Datum  Thema: Regel (kurz, technisch).
       Entscheidende Funktion: <name>.  Begründung/Quelle: <Feld/Log>.
```

2026-06-04  **Stroh-Logistik (Strohballen)** ergänzt — vorher fehlte sie komplett. Ballen wurden nur auf Gras-Feldern gesampelt (`shouldSampleBales = isGrassCropField or hasTrackedBales`), auf Getreide-Stoppelfeldern also nie → Strohballen unsichtbar; und es gab nur `grass_*`-Aktionen. **Lösung:** (1) Ballen werden nun **typ-klassifiziert** über den Fülltyp (`Bale.getFillType`/`.fillType` → `g_fillTypeManager`): `STRAW`→straw, `DRYGRASS_WINDROW`/`SILAGE`/`GRASS_WINDROW`→grass, sonst other (`FieldAdvisor.classifyBaleKind`, memoisiert je Index). `sampleBaleCoverage` zählt `{total,straw,grass,other}`. (3) Neue Aktionen im `post_harvest`-Acker-Zweig: Strohballen am Feld → `straw_bale_collect` (auto, fertig wenn Strohballen = 0); sonst bei strohgebenden Früchten (`STRAW_PRODUCING_FRUITS`: Weizen, Gerste, Hafer, Raps, Roggen, Triticale, Sorghum, Soja — **nicht** Mais/Sonnenblume) → `straw_bale` „Stroh pressen/bergen" (auto, fertig wenn Strohballen erscheinen). Diagnose: `ftdlDump` zeigt jetzt `baleCoverage: total/straw/grass/other` + je Feld-Ballen `fillType`/`kind`.
            Entscheidende Funktion: `FieldAdvisor.classifyBaleKind` + `addEmptyOrPostHarvestActions` (Stroh-Zweig) + `FieldTaskCompletion.isGrassLogisticsComplete` (straw-Zweige). 2026-06-04  **Grundstücks-Felder (eigene Felder ohne vordefinierte Feld-ID)** — **immer an, kein Toggle**. Pseudo-Field-Wrapper (`buildFarmlandPseudoField`) liefert `getId()` (= `FARMLAND_PSEUDO_ID_OFFSET 1_000_000 + farmlandId`, kollisionsfrei) und `getCenterOfFieldWorldPosition()`; der Rest des Scans/Advisors probt rein per Weltposition (`getEnrichedFieldState`→`FieldState:update`), braucht also kein echtes Field-Objekt. `getEngineFieldById` macht Pseudo-IDs reversibel (für Tasks/Auto-Erledigen/`refreshFieldRecordSync`). **Warum kein Toggle nötig (perf):** Enumeration läuft **nur** im Overview-Scan-Pfad (Menü offen / Rescan), **nie** im Update-/HUD-Loop; Grundstücke **mit** Feld werden über `farmland.field` billig übersprungen (keine Probe); nur die wenigen feldlosen eigenen Parzellen bekommen **eine** Center-Probe (kein Density-Map-Loop). Diagnose: Konsole `ftdlFarmlands` listet Eignung pro Grundstück.
